# Pocket POS — working notes

Preact + TypeScript PWA, IndexedDB storage, packaged to Android with Capacitor. See README.md for features and commands.

## Commands
- `npm test` (vitest, fake-indexeddb) · `npm run build` (typecheck + vite) · `npm run apk` → `releases/pocket-pos-debug.apk`
- Android build needs **JDK 17–24**. JDK 25 breaks Gradle ("Unsupported class file major version 69"); `scripts/build-apk.sh` prefers a JDK in `.tools/`.

## Invariants — don't break these
- **Money is integer minor units** everywhere (`src/lib/money.ts`). Never store floats. Tax/discount allocation uses largest-remainder (`allocate` in `cart.ts`) so line figures always sum to order totals. Ingredient unit costs are fractional *only* inside `recipe.ts`; the product's `cost` is rounded to whole minor units.
- **Backup format** (`src/lib/backup.ts`): changing the shape of a stored record means bumping `BACKUP_SCHEMA` and adding a `MIGRATIONS` step so old files still restore (checksum is verified on the file as written, *then* migrated). A new object store must be added to `BACKUP_STORES` **and** the IndexedDB `upgrade()` in `db.ts` (guarded by `oldVersion`). Optional new fields on existing records need neither.
- **Restore is all-or-nothing**: a sync throw inside an IndexedDB transaction does NOT abort it — `restoreBackup` calls `tx.abort()` explicitly. Keep that and the "failed restore is all-or-nothing" test.
- After a restore, call `loadAll()` **before** `saveSettings()`, otherwise stale in-memory settings overwrite the restored ones (`applyRestore` in `store.ts`).
- **Payment-proof photos** live in their own `attachments` store (not inside orders). A backup/snapshot made *without* them has `attachmentsIncluded: false`, and restoring it must not delete the device's photos. Automatic snapshots skip photos; pre-restore/reset snapshots keep them.
- **Automatic backup** (`lib/autobackup.ts`, `screens/AutoBackup.tsx`, `BackupFolderPlugin.java`): Android only. The user picks a folder once (Storage Access Framework tree URI, persisted grant, no storage permission). Config (folder, frequency, password…) is **device-local in localStorage**, never in a backup. Runs from startup / app resume / 30-min timer / shift close — there is no background service (IndexedDB is only reachable from the WebView). Files are `pocketpos-auto-YYYYMMDD-HHMMSS[.enc].json`; pruning keeps the newest 7 and only ever deletes names matching that pattern. `lastBackupAt` advances only on success. Native errors are short codes (`folder-unavailable`, `write-failed`) translated in `describeError`. Pure rules (`isDue`, names, `copiesToDelete`) and the whole run (fake folder via `deps`) are unit-tested; the real picker/grant needs the emulator (`adb shell mkdir /sdcard/Documents/X` first — the picker refuses the storage root).
- **Categories**: `Category.enabled?` (missing = on) and `Category.preset?` are optional, so no schema bump. Library data is `lib/categories.ts` — names are `() => t('…')` so the i18n scanner sees every literal; names must stay **distinct within each language** (a library entry also matches an existing category by name; `i18n.test.ts` enforces it). Turning a category off only hides it (Sell chips, item form); items keep it. Bulk item move is `moveProducts()`; item multi-select registers with `registerSheet` so back leaves it first. Icons come from `lib/emoji.ts` — keep to Unicode ≤ 12 so older Android phones don't show empty boxes.
- **Pending orders** (`parkCart` / `recallParked` / `cancelPending` / `cancelCart` in `store.ts`, `PendingSheet` in `Sell.tsx`): a pending order is a `Parked` record holding a `CartState`; it becomes an `Order` only in `checkout()` (stock, points and the receipt number move then). Optional `CartState.paid` = deposits (`Payment.deposit`), `CartState.proofKey` = where the deposit's slip photos wait in `attachments` (keyed by it instead of an order id; `checkout` re-keys them to the sale, `backup.ts` keeps them because a parked order owns them). Recall **deletes** the parked record — the live copy is `cart` (localStorage) — so anything that clears the cart with deposits must go through `cancelCart()`, which returns the deposits to hand back. **Drawer accounting:** a cash deposit is written as a cash-**in** movement in the open shift when taken, and `shiftSummary` skips `deposit` cash payments on the finished order so it isn't counted twice (card/e-wallet deposits are not drawer money). Deposits larger than a reduced total are trimmed newest-first in `settleDeposits` and the excess is booked as cash-out. No points as a deposit; with `requireShift`, no deposit without an open shift. `applyRestore` parks a part-paid cart first so it lands in the safety copy.
- **Sell grid quick edit**: a tile in the order gets the `.tile-qty` strip laid over its price row (absolutely positioned, so adding the first unit never shifts the grid — keep it that way). `removeOne()` only acts when the item is on one line; otherwise `ProductLinesSheet` asks which. Tiles are a `div.tile-cell` wrapping the `button.tile` and the strip (no button inside a button).
- **Pictures** all go through `lib/image.ts` `pick()` → the crop/rotate/adjust editor (`ui/ImageEditor.tsx`, registered with `setImageEditor`; tests run without one). Crop maths is pure and normalised in `lib/crop.ts`. Keep the editor's picture **inset from the screen edges** — handles at the edge sit in Android's gesture-navigation back zone and a drag there closes the screen.
- **Item names**: `Product.names` / `namesAuto` (machine-made, untouched-by-a-person) and `Settings.nameLang / nameLangs / autoTranslate / receiptNameLangs` (≤ 2). Pure rules in `lib/names.ts` (a hand-typed name is never overwritten except by that language's own ↻); background fill in `lib/nameTranslate.ts` queues one item at a time and re-reads the item before saving. Translation is Google ML Kit on the phone (`TranslatePlugin.java`), not a web service; zh-TW can't be a target. Show names with `productName()` / `lineName()`; receipts use `receiptNamer(settings)`. Search with `nameMatches`.
- **Bluetooth printing**: the receipt is drawn at the printer's dot width (`renderForPrint`) and sent as an ESC/POS raster (`lib/escpos.ts`, pure, round-trip tested); `lib/printer.ts` config is device-local; `BluetoothPrinterPlugin.java` lists *paired* devices only (BLUETOOTH_CONNECT on 12+, no scanning) and writes over classic SPP. Not hardware-tested.
- **i18n gotcha**: before reusing an existing English key, check what it means in the language files — `t('Free')` is "free of charge", not "free-form". The test only checks a key exists, not that it fits.
- **Receipt content lives in one place**: `buildReceipt()` in `src/lib/receipt.ts` returns a `Block[]` (logo / text / row / rule). Three renderers draw it — `receiptText` (monospace, for chat and thermal paper), `Paper` in `screens/Receipt.tsx` (HTML, scales with Display size, prints), and `lib/receiptImage.ts` (canvas → PNG / PDF via `lib/pdf.ts`). Add or reorder receipt content in `buildReceipt` only; `receipt.test.ts` pins the text layout. The PDF is one JPEG page (so every script renders without embedded fonts).
- Shop logo is a small data URL in `settings.logo` (≤ ~90 KB, flattened on white by `fileToLogo`); it travels with settings in backups. Optional new settings fields need no schema bump — `loadAll` merges `defaultSettings()` under the stored record.
- Records carry `updatedAt` (set by `put`); merge-restore relies on it.
- Recipe-costed items: `product.cost` is derived in `saveProduct`; call `recomputeRecipeCosts()` after ingredient changes. Sale lines snapshot `unitCost`, so history never changes.

## i18n
- The English text is the key: `t('Add customer')`, `tn(n, '{n} item', '{n} items')`, placeholders like `{name}`. Missing entries fall back to English.
- Any new user-visible string must be added to **every** `src/i18n/*.ts` — `src/i18n/i18n.test.ts` fails if a language is missing a key, drops a `{placeholder}`, has an orphan entry, or contains invisible characters. `node scripts/i18n-keys.mjs --json` lists the keys.
- Don't call `t()` at module load for labels (not reactive) — use functions/inside render. Don't name a local variable `t`.
- Language: phones → system language, desktop browsers → English, user override in Settings; stored in `localStorage` (device-local, not in backups). Same for display size / high contrast (`src/lib/display.ts`).

## Layout / display size
- CSS sizes are in **rem** (root font-size = 16px × `--scale`), so "Display size" scales everything. Don't add `px` sizes (hairlines ≤3px are fine). Breakpoints are classes (`.bp-420/560/720/900`) set from `innerWidth ÷ scale` in `display.ts` — don't use `@media (min-width)`.
- `.banner` is a flex row: wrap text that mixes inline elements in a single `<div>`.
- Preact controlled inputs don't re-render when sanitised state is unchanged, so stray characters stay visible. Use `digitsOnly` / write the cleaned value back to the DOM (see `components.tsx`).

## Android
- Native vs web differences live in `src/lib/platform.ts` (file save via share sheet, `<a download>` doesn't work in WebView). The service worker is registered only off-native.
- `ContactPickerPlugin.java` (local) uses the system picker, so **no READ_CONTACTS**. Do not add `@capacitor-community/contacts` (it requests read+write contacts).
- The manifest needs `<queries>` for `IMAGE_CAPTURE`, otherwise Capacitor's file chooser can't see the camera app and "Take photo" silently opens the gallery on Android 11+.
- A file chooser only opens from a real user tap (scripted `.click()` is blocked); `pickFile` resolves null on window focus as a failsafe when `cancel` never fires.
- Back button (`lib/sheets.ts`): every `Sheet` registers a close callback on one stack; `handleBack()` closes the top one, else asks the app (`setEmptyBackHandler`: leave a tab), else the platform takes over. **Android handles back entirely in JS** via Capacitor's `App` `backButton` event (root → `minimizeApp`, which keeps a sale in progress alive). Do not go back to walking WebView history with guard entries there: Chromium marks script-added entries skippable, `canGoBack()` turns false, and Capacitor's default handler then silently ignores back (symptom: Settings couldn't be closed after a few presses; no popstate, no exit). The browser/PWA still uses one history guard entry + `popstate`. Anything that isn't a `Sheet` but has its own "back" (setup wizard steps, the in-app scanner) must call `registerSheet` too. Test back on the emulator with `KEYCODE_BACK` *and* the edge swipe, repeatedly, not just once per screen.
- The APK includes only arm64 + armeabi-v7a (`abiFilters` in `android/app/build.gradle`) because the translator's native library is 12–17 MB per CPU; use `-PallAbis` for an x86 emulator.
- After changing web code for the APK: `npm run apk` (does build + `cap sync`).
- `uiautomator dump` of the WebView can lag or show the screen underneath an open sheet; for emulator tests prefer WebView DevTools (`adb forward` + a small CDP script) to read DOM state, and tap by coordinates computed from `getBoundingClientRect() × devicePixelRatio` (+ the status-bar offset).
- Debugging on the emulator: WebView DevTools is available over `adb forward tcp:<port> localabstract:webview_devtools_remote_<app pid>` (port 9222 is often taken by other tools).
